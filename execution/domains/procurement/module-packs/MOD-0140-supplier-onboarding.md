## 1. Module Summary
Tedarikçi master + onboarding (KYC / sanctions / doküman / onay) SoR'u. Hedef kullanıcı: procurement operatörü + onaylayan. Supplier kimliği + durum + iletişim yüzeyi MVP-6 (0147 performance, 0148 portal) tarafından tüketilir (frozen slice). Blueprint W-1, Procurement Suite / P2P.

### 3.1 `SupplierEligibility` — uygunluk şeması (1.3.0, Revizyon 2)

Bu yüzden yeni şemalarda null **yalnız** 2020-12 biçimiyle yazılır: düz tipte `type: [string, "null"]` / `type: [boolean, "null"]`, `$ref`'li enumda `oneOf: [{ $ref: … }, { type: "null" }]`. Dosyanın 1.2.0 metnindeki `nullable: true` deseni yeni şemalarda **kullanılmaz** (1.2.0'daki yerleri değişmez — §3.3 "bilinen"). Entegrasyon E-3 "uuid ile oku" ihtiyacı bu uçla karşılanır. - **`GET /eligible`** (`listEligibleSuppliers`): çağıran şirketle **silinmemiş ve `status = Active`** ilişkisi olan tedarikçiler — yani **tam olarak** `eligibleForTransactions = true` olan ilişkiler (S-1 kararı, Natig 2026-10-28: tanım ve liste kuralı aynıdır, her öğede `eligibleForTransactions = true` değişmezdir; onboarding onayı ya da `purchasingEnabled` listeyi süzmez, öğede alan olarak döner). Parametre yalnız `cursor` (string, opsiyonel); sayfa boyu `listSuppliers` ile aynı (50, `GetSupplierListHandler.cs:12`); ek filtre yok (gerekirse sonraki eklemeli sürüm). **Sıralama ve imleç (Revizyon 3, F-2):** kararlı sıralama **yalnız** kanonik `SupplierId`'ye göre, ordinal (`StringComparer.Ordinal` / Mongo'da ikili karşılaştırma) artan; imleç = bir önceki sayfanın **son döndürülen** öğesinin `SupplierId`'si; süzgeç `SupplierId > cursor` (ordinal); `nextCursor` = daha fazla öğe varsa sayfanın son öğesinin `SupplierId`'si, yoksa `null`. Sıralama ve süzgeç sayfalamadan **önce**, uygun kümenin tamamına uygulanır. Bu uç `listSuppliers`'ın `Name` → `SupplierId` sıralamasını (`GetSupplierListHandler.cs:29-37`) **kullanmaz** ve ondan imleç kodu paylaşmaz: orada sıralama `Name`'e göre, süzgeç `SupplierId`'ye göre olduğundan adı sonra gelip kodu küçük olan tedarikçiler sonraki sayfada atlanır ya da tekrar eder — bu `listSuppliers`'ın önceden var olan kusurudur, burada düzeltilmez (§20). Yanıt `200` → `{ items: SupplierEligibility[], nextCursor: string | null, contractVersion: string }` (`listSuppliers` zarfının alanları; `nextCursor` 3.1 biçimiyle `type: [string, "null"]`, §3.3). Kiracı + LE kapsamlı; başlıkta seçilen / JWT'deki LE dışında bir şirketin ya da başka kiracının verisi listelenmez (yabancı/pasif LE başlığı → 404 `UNKNOWN_LEGAL_ENTITY`, §8 C2; kullanıcının o LE'ye yetkisi doğrulanmaz — bilinen sınır, §8, S-7). Yol sırası: `/eligible` somut yoldur, `/{supplierId}`'den önce eşleşir (OpenAPI somut-önce kuralı; ASP.NET literal segment önceliği); sunucunun verdiği kodlar `SUP-` önekli olduğundan `eligible` bir tedarikçi kodu olamaz.

### 3.3 Sözleşme 1.3.0 — hata yanıtları ve 3.1 null yazımı, birebir YAML (Revizyon 3, F-1)
**Sorun (inceleme F-1):** OpenAPI'de bir işlemin bir durum kodu için tek yanıt nesnesi vardır. getSupplier, updateSupplier, deleteSupplier, getOnboardingCase ve submitOnboardingCase'te `'404': { $ref: '#/components/responses/UnknownSupplier' }` zaten var (`supplier.openapi.yaml:87, :100, :110, :170, :190`); ikinci bir `404 UnknownLegalEntity` eklenemez, mevcut nesneyi yeniden kurmak da §2 yalnız-ekleme kuralını çiğner.

## 13. Failure Path to Verify
- **Duplicate active TaxId** (kiracı + ülke + normalize vergi no; başka şirkette de) → 409 + mevcut `supplierId` + "bu şirkete bağla" + kayıt yok + reload temiz (K-6).
- **Aynı şirkete ikinci bağlama** → 409, ikinci ilişki yok.
- **Ortak alan güncellemesi `master.update` izni olmadan** → 403; **kiracı geneli arama `read-tenant-wide` olmadan** → 403.
- **Başka şirketin ilişkisini okuma/değiştirme** ya da ilişkisi olmayan şirkette erişim → 404.
- **Blocked / OnHold ilişkiyle yeni PO / fatura / RFx-teklif / sözleşme** → red, kayıt yok (K-7, DL-6).
- **Uygunluk — ilişki yok (Revizyon 2, karar):** `POST /validate` → **200**, satırda `known: false`, `relationshipExists: false`, diğer uygunluk alanları `null`, `eligibleForTransactions: false` (toplu denetim; kod kiracıda başka şirkette olsa da `supplierMasterId` dönmez). `GET /{supplierId}/eligibility` → **404 `UNKNOWN_SUPPLIER`** (bugünkü izolasyon davranışı; kod ya da uuid fark etmez). `GET /eligible` → o tedarikçi listede yok.
- **Uygunluk — ilişki var ama Blocked / OnHold / Inactive** → `relationshipExists: true`, `status` gerçek değer, `eligibleForTransactions: false`; `/eligible` listesinde yok.
- **Uygunluk — ilişki Active ama onboarding `InReview` / `Rejected` ya da `purchasingEnabled: false` (S-1, 2026-10-28)** → `eligibleForTransactions: true`, `/eligible` listesinde **var**; `onboardingStatus` / `purchasingEnabled` gerçek değerleriyle döner — reddetmek tüketicinin işidir (Procurement burada süzerse hata).
- **Uygunluk — silinmiş ilişki** → `GET /{supplierId}/eligibility` 404; `validate` satırı `relationshipExists: false`.
- **Dar izinle tam kayıt okuma:** yalnız `procurement.suppliers.eligibility.read` taşıyan çağıran `GET /api/suppliers`, `GET /{supplierId}`, `GET /{supplierId}/onboarding` → 403 (iletişim, vergi no, onay ayrıntısı açılmaz).
- **Yabancı / pasif / bilinmeyen LE başlığı (C2)** → her Procurement kiracı ucunda 404 `UNKNOWN_LEGAL_ENTITY`, hiçbir okuma/yazma yok; **çağıranın rolünde `mdm.legal-entities.read` yok** (MDM 403; S-2, 2026-10-28) → **403 `LEGAL_ENTITY_LOOKUP_FORBIDDEN`** (503 değil), hiçbir okuma/yazma yok, yeniden deneme yok; **MDM'e ulaşılamadı** (zaman aşımı, 5xx, ağ, bozuk gövde, MDM 401) → 503 `DEPENDENCY_UNAVAILABLE`, hiçbir okuma/yazma yok (fail-closed); MDM 401 → 503 sahip kararıdır (Natig, 2026-10-28; Revizyon 4, F-1).
- **Onboarding onaya gönderim — MOD-0023 şablonu yok / MOD-0023 erişilemez** → 409 / 503, ilişki `InReview` olmaz, `WorkflowInstanceId` yazılmaz; tekrar gönderim aynı idempotency anahtarıyla ikinci örnek açmaz; ret sonrası yeniden gönderim eski (terminal) örneği almaz, `r{n+1}` ile yeni örnek açar (Revizyon 3).
- **Workflow sonucu başka bir örneğe ait** (ilişkinin sakladığı `WorkflowInstanceId` değil) → uygulanmaz; MOD-0023 okunamazsa onboarding okuması 200 döner, durum `InReview` kalır.
- **Servis token'ı (DL-7):** yanlış audience / listede olmayan `service_name` / süresi dolmuş / eksik-fazla claim / `iat ≠ nbf` / `exp ≠ nbf + 300` → 401; `X-Tenant-Id` ≠ `tenant_id` → 401; izin verilen iki uç dışındaki uç — **`GET /eligible` dahil** (S-4, 2026-10-28) — → reddedilir (401/403, hiçbir zaman 200); yabancı LE → 404; Procurement → MDM servis kimliği yoksa → 503.
- **Missing Name** → 400 + validator mesajı + save engellenir.
- **Concurrency conflict** (stale update) → 409 + "kayıt değişti, yeniden yükle" + sessiz overwrite YOK.
- **Unauthorized actor** (izin yok) → 403 + action disabled/permission-denied (UAS-001: iskelet çizilmez, yönlendirme yok).
- **Cross-tenant/LE erişim** → 404 (sızıntı yok).
