## Options

| Option | Effect on scope | Effort (O/M/P) | Risk |
|---|---|---|---|
| **A — Shipment-only exception, verify A05 and A06 separately (recommended)** | Section-key equality is switched off for this profile. Each create field must sit in an accessible create section, and each required detail fact in a detail section. Detail-only data creates no form section. | Inside the DN-02 profile work (0183-6-REMAINING 12/20/36 h). | Low. Keeps the frozen 13-input create boundary. |
| B — Enforce exact section parity | An explicit UI design and source decision plus a new presentation successor. No new editable business fields are allowed. | UNESTIMATED. | Medium to high. Reopens accepted UI; FAIL 03 controls until the redesign passes. |

**Reason for A:** create and detail have different, approved field sets. Forcing one section map would either add empty
sections or push read-only facts into the create form, which A05 forbids.
