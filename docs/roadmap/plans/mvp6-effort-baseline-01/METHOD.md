# Effort baseline E1 — 2026-09-24

This is a provisional analyst estimate, not measured labor, time tracking, owner-approved final scope, or statistical forecast. Units are equivalent specialist active hours at a consistent reference pace; they are NOT agent runtime or token-hours. AI acceleration has not been calibrated. Approval waits and idle wall time are excluded.

Each row is a delivery subpackage. DELIVERED credit is retrospective estimated replacement effort for evidenced work, not historic hours spent. REMAINING estimates cover still needed work. Completed and remaining subpackages are separated instead of assigning an arbitrary 80%-done fraction. Previously failed/discarded runs are not earned work. Rework remaining increases the denominator; repetition never increases earned credit.

Category hours are directly estimated from scope complexity: lifecycle/transaction/replay/security complexity, screen workflows, cross-service boundaries and verification depth. They are not proportional to files, tests or prompts. Most-likely baseline rows are judgment estimates; no measured velocity dataset exists. Counts in evidence are provenance only. Pack/contract hours represent delivery work, not each repeated report. Backend implementation excludes independent verifier labor; Test/VER explicitly includes that separate work. Shared Auth/MDM, Supplier producer seams, cross-module G5 and operational readiness have separate SHARED rows and are not duplicated in module rows.

Rate per category/module = delivered most-likely effort / (delivered + remaining most-likely effort). Portfolio uses all module AND SHARED hours, never averages module percentages. Bounds = delivered-low/(delivered-low+remaining-high) and delivered-high/(delivered-high+remaining-low). These are sensitivity bounds, not confidence intervals. Optimistic/pessimistic values are transparent multipliers, not independently elicited three-point estimates: delivered 0.75–1.25; remaining 0.6–1.6, or 0.6–2.0 for UI/Supplier/shared uncertainty. Do not report P50/P90 or a finish date from them.

Full frontend detail is not frozen for eight modules. UI estimates are explicit minimum-surface reserves; final scope can change them. Live upstream replacement is a bounded integration reserve, not authorization to implement real optimization, automatic inventory postings, financial settlement or Supplier producer changes. These excluded optional expansions need separately estimated scope decisions. Contract/pack work remains required where decisions are missing. Waiting days have no effort credit and require a separate dependency schedule.

Evidence is report-based: source reports were read and hashed. No runtime tests, raw archive revalidation or full repository absence audit was performed. The inspected NumericDate handoff contained blank reference fields; the subsequent user handoff supplies exact artifact hashes, but candidate completion still is not application or independent acceptance. BC v3 uptake is credited as completed, superseding stale claims that it was absent. Shared checkout deployment remains separate.

This baseline supersedes use of 48/52.5/66.7 as work-volume percentages. Do not compute percentage-point progress between different models. Future updates require row-level scope and estimate deltas with reasons. Actual lane effort tracking can later recalibrate estimates. Current estimates are low/medium confidence and must not be sold as exact percent of an exhaustively specified product.
