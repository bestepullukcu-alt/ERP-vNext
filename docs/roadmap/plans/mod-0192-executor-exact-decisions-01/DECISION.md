## Tek önerilen execution policy

| Karar | Exact öneri ve gerekçe | Acceptance oracle |
|---|---|---|
| Claim/attempt | Evaluation Accepted iken veya Running lease süresi dolmuşken tek scoped atomik CAS/transaction, `status + version + fence + leaseUntil` değerlerini yazar ve `attempt` değerini **aynı başarılı claim'de bir artırır**. Başlangıç `attempt=0`; başarılı claim'ler 1, 2, 3'tür. Kaybedilen CAS sayılmaz; claim sonrası crash/expiry sayılır. Böylece process kaybı sınırsız bedava deneme üretmez. Her claim yeni, önceki fence ile eşleşmeyen monoton lease generation alır. | İki worker aynı Accepted kayda saldırınca birinin `attempt=1` yazdığı, ötekinin 0 modified ile döndüğü; ilk worker claim sonrası ölünce yeniden claim'in `attempt=2` olduğu kalıcı DB verisiyle ölçülür. |
| Saat ve lease | Claim, renew, expire ve terminal validity karşılaştırmalarında **Mongo primary'nin server UTC saati** kullanılır; app/process wall clock veya JWT/request saati kullanılmaz. Claim/renew atomik sunucu işlemi `leaseUntil = serverNow + 30s` üretir; eşitlikte lease expired kabul edilir. Mongo `$dateAdd`/`$$NOW` gibi server-side işlemlerin hedef sürümde çalışması Phase 1.5 teknik kapısıdır. 30s yalnız reclaim için en erken niyet edilen sınırdır. | İki process saatini ±2 dakika kaydırınca claim/renew/terminal kararı değişmez; lease dolmadan ikinci claim yoktur, server-time expiry sonrası tek claim kazanır. |
| Renewal/loss | Running işi canlıyken ayrı 10s heartbeat, yalnız geçerli `status=Running`, `version`, `fence` ve henüz dolmamış lease eşleşirse lease'i `serverNow+30s` uzatır. Renew attempt artırmaz; version artırılıyorsa yeni version aynı işçiye döner ve terminal CAS onu kullanır. CAS/DB hatası veya süre aşımı ile yenileme kaybedilirse işçi hesaplamayı durdurmaya çalışır ve terminal yazısını denemez; durdurulamaz hesaplama bitse bile terminal fence reddeder. 10s heartbeat/scan yapılandırılmış aralıktır, zaman garantisi değildir. | Uzun fixture çalışırken en az iki renew ile `attempt=1` kalır. Heartbeat durdurulup lease expire edilince ikinci worker `attempt=2` alır; ilk worker'ın sonucu kalıcı etki yaratmaz. |
| Stale terminal fence | Terminal transaction, scoped evaluation üzerinde `Running + current version + current fence + serverNow < leaseUntil` koşuluyla tek kazanan CAS yapar. CAS 0 ise stale worker aggregate, active slot, audit veya outbox yazamaz. Yalnız local hesap bitmiş olması commit yetkisi vermez. | Eski fence ile delayed Completed ve yeni fence ile Failed/Completed yarıştırılır; yalnız yeni fence'nin terminal sonucu kalır, tam bir terminal audit/event görülür. |
| Terminal atomiklik | Kazanan terminal Mongo transaction'ı **birlikte** yazar: `Completed`/`Failed` + literal oracle veya failure sonucu + `completedAt` + version; active-slot release; tek terminal audit; tek `capacity.evaluation.completed.v1` Pending outbox. `occurredAt=completedAt`, original submit correlation ve scenario-created causation C192-06 önerisinden korunur. `(tenant, LE, evaluationId, terminal-event-type)` unique effect anahtarı ikinci terminal insert'i engeller. Majority commit outcome belirsizse scoped evaluation ve event/audit kimlikleri okunur; kör ikinci terminal insert yapılmaz. | Terminal transaction'ın her write-stage'inde process/fault: ya dört etki birlikte görünür ya hiçbiri. Unknown commit sonrası read/retry bir terminal event ve audit ile sonuçlanır; Pending event yayınlanmış sayılmaz. |
| Üçüncü deneme/process kaybı | Claim 3 hesap bitirip geçerli lease ile terminal yazarsa normal Completed/Failed. Üçüncü claim crash/expiry ile sonuçlanırsa startup/scan, **dördüncü claim veya fixture hesaplaması yapmadan**, `Running + attempt=3 + current version/fence + leaseUntil<=serverNow` koşullu CAS ile atomik `Failed` terminal transaction'ını yürütür. Deterministic fixture input rejection herhangi bir denemede aynı terminal Failed yolunu kullanır. Önce belirsiz terminal commit sonucu okunur; committed terminal varsa expiry-fail yapılmaz. | Üç ayrı claim sonrası kill/restart, son lease expiry ve scan: `attempt=3`, `Failed`, active slot boş, tek audit/Pending event. Dördüncü fixture invocation sıfır. Son claim terminali commit etmişse restart sadece mevcut sonucu görür. |
| Hesaplama ≠ commit | Process kaybı/renewal race nedeniyle literal fixture oracle birden çok kez çalışabilir. Garanti edilen yalnız **tek durable terminal commit/effect**tir; exactly-once çalıştırma veya Event Bus teslimi değildir. Executor Accepted commit signal'ı, startup ve 10s scan ile ilerler; publisher kapalıyken de terminale ulaşır ve event Pending kalır. | İki worker'ın oracle invocation sayısı 2 olabilir; DB terminal transition/audit/outbox sayısı 1'dir. Publisher kapalı testte evaluation terminal, event Pending; publisher yeniden açılması evaluation'ı tekrar çalıştırmaz. |

Bu politika tenant/LE ve soft-delete filtrelerini bütün claim, renew, scan, terminal ve receipt okumalarında zorunlu tutar; active slot `(TenantId, LegalEntityId, CapacityPlanId, ScenarioId)` tekilliği durable unique index ile korunur ([C192-05](../mod-0192-exact-policy-01/DECISION-PACK.md), [repository standard](../../../.antigravity/rules/repository-standard.md), [Mongo index standard](../../../.antigravity/rules/mongo-indexing.md)). Submit'in orijinal 202 receipt'i tekrarında saklanan business response döner; GET güncel terminal durumu okuyabilir. Different-key aktif çakışma frozen 409 `EVALUATION_ALREADY_ACTIVE`dir. Changed-payload same-key ve invalid constraint wire davranışları ayrı unpublished amendment kararlarına bağlıdır; bu executor kararı onları onaylamaz.

## Failure/restart kabul matrisi

| ID | Kesme noktası / negatif | Ölçülecek exact sonuç |
|---|---|---|
| X01 | Accepted transaction commit öncesi kill | Aggregate/receipt/slot/audit/outbox yok; unknown commit ise önce DB sonucu okunur. |
| X02 | Accepted commit sonrası HTTP 202 kaybı | Accepted + original 202 receipt + slot tek; same-key replay ikinci iş üretmez, restart scan devam eder. |
| X03 | Claim 1 sonrası kill, lease geçerli | Running/attempt=1/fence/lease kalıcı; başka claim yok. Expiry sonrası tek claim 2, eski fence terminal 0 modified. |
| X04 | İki worker aynı expired lease'i görür | Tek claim CAS kazanır; oracle iki kez hesaplanabilse de yalnız yeni fence terminal commit eder. |
| X05 | Renewal gecikmesi/DB kaybı | Eski worker terminal etkisi sıfır; sonraki claim attempt artırır; local cancellation başarısı single-commit için şart değildir. |
| X06 | Terminal transaction precommit fault | Terminal/slot release/audit/Pending event dördü de yok; geçerli lease/expiry politikasına göre tekrar denenir. |
| X07 | Terminal unknown commit / response loss | DB okuması all-or-none sonucu ayırır; committed ise tek terminal effect, uncommitted ise yeni geçerli claim/fence ile ilerleme. |
| X08 | Üçüncü claim sonrası process kaybı | Expiry sonrası Failed tek transaction; claim 4 ve oracle invocation 4 yok. |
| X09 | Publisher yok; restart | Accepted/Running fixture evaluation terminale ilerler; terminal event Pending kalır; GET read-only ve tekrar değerlendirme yok. |
| X10 | Farklı tenant/LE veya soft-deleted kayıt | Scan/claim/renew/terminal eşleşmesi yok; foreign slot, audit veya outbox yazımı yok. |

Her X senaryosu izole Mongo replica set, gerçek ayrı process/restart, request izi ve persisted evaluation/receipt/slot/audit/outbox ölçümü gerektirir. Model/schema PASS E4 kanıtı değildir. `10s / 30s / 3` **recovery deadline, exactly-once execution veya publisher teslim garantisi vermez**.
