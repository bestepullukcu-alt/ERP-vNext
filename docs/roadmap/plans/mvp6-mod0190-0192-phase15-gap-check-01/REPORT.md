## Mongo 8.0.18 server-time feasibility — bounded technical check

Installed `mongod` is **8.0.18**, `mongosh` **2.6.0**, SupplyChain Persistence references `MongoDB.Driver 2.27.0`. Official MongoDB docs say `$$NOW` supplies a deployment-consistent current datetime in aggregation expressions, `$dateAdd` computes a date offset, and `findOneAndUpdate` accepts update pipelines ([variables](https://www.mongodb.com/docs/manual/reference/aggregation-variables/), [dateAdd](https://www.mongodb.com/docs/manual/reference/operator/aggregation/dateAdd/), [update pipeline](https://www.mongodb.com/docs/manual/tutorial/update-documents-with-aggregation-pipeline/)). A separate temporary standalone `mongod` on **127.0.0.1:63319**, never operational 27017, executed scoped `$expr` expiry filter plus pipeline `$$NOW+$dateAdd(30s)` claim and renew: claim attempt/version 1, duplicate pre-expiry claim null, renewal succeeded without incrementing attempt; exit 0. Exact script and raw output: [mongo_server_time_probe.py](mongo_server_time_probe.py), [MONGO-SERVER-TIME-SMOKE.json](MONGO-SERVER-TIME-SMOKE.json). The first sandboxed attempt could not bind a socket (`PermissionError: Operation not permitted`); the same isolated probe then succeeded with permitted localhost execution. This proves expression syntax on local 8.0.18 only. It did **not** use a replica set, transaction, C# driver, process race or production data and is **not** E4/lease-policy acceptance. The required exact future test remains a scoped replica-set CAS/renew/terminal transaction with two processes and clock-skew/restart assertions.
