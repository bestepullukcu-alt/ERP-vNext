1. Old plans claim service/E4 absent and the continuation still awaits central acceptance.
   Central acceptance now exists. New v2.0 supersedes those current-state statements; old bytes stay intact.
2. Remaining work was repeatedly expressed as generic approval/preparation. Technical evidence narrows it:
   four Carrier create422 examples conflict with no-details policy. Plan targets that disposition first.
3. Draft0185/0186/0187 have no demonstrated runtime Carrier consumer. Their review is design/dependency
   disposition, not imaginary SDK runtime acceptance. External consumer completeness remains unknown.
4. Prepublication conformance, postpublication uptake and postimplementation E4 were conflated as potential
   circular prerequisites. Plan distinguishes them; a finished Carrier service is not required to begin DEV.
5. Previous evidence lanes wrote separate paths in one checkout. Preservation PASS does not meet SOP's
   separate-worktree parallel writer requirement. Future writers are serialized or use separate worktrees.
6. Strict Profile C/VER cannot write repository reports/scripts. Future reviewers return evidence outside
   repo and CT persists it; test/fixture-writing is a distinct writer task, not an independent verdict lane.
7. Carrier composition has concrete middleware/model-error/replay hazards; plan requires isolation and
   Shipment regression after authorized composition changes.
8. Protected baseline171/172 plus one changed Carrier draft must not be stated as172/172 unchanged.
   New evidence artifacts are separate from the accepted151-entry implementation package.
9. External failures are user-deferred, not a formal waiver with invented owner/expiry. Repository gate
   remains BLOCKED; deferred unrelated failures do not automatically block bounded approved slice work.
