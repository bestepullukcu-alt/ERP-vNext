## Exact harness correction

The parent therefore inserted `Accepted` with string `_id`/TenantId/LegalEntityId and the child's typed scope query matched zero rows. The prior child returned success when `ClaimAsync` returned null, so the parent discovered the failure only as `Accepted` versus `Running`.

The child now reads the one raw evaluation before constructing a typed collection. If its `_id` is a BSON string, it registers the same GUID and DateTimeOffset serializers as normal persistence startup **inside that child test process only**; if `_id` is legacy BSON binary, it keeps the driver's existing targeted-run representation. It checks a raw tenant/legal-entity scope query and then the typed tenant/legal-entity/soft-delete query find the same evaluation. In `claim-terminal` mode a null lease now fails the child rather than silently passing. Child test output uses normal verbosity so failures carry a useful stack. No shared serializer registration source or parent/global process state was changed. The final Mongo observation shows string scope count 1 versus wrong binary scope count 0, completed attempt/fence 2, and one Pending terminal outbox event.
