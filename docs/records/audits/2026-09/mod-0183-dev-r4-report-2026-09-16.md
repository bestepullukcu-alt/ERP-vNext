## Warehouse and Inventory mapping

WarehouseReadClient supports only GET list and GET detail at the frozen paths.
The coordinator always fetches authoritative detail using outboundId; it accepts
no notification-provided lines/address. New creation requires ReadyToShip.
Clients forward validated tenant/LE scope and bearer credential, plus supplied
correlation. The coordinator/client classes are production code exercised through
explicit test construction. No caller/hosted activation is registered.

| Source | Internal/Shipment treatment |
|---|---|
| outboundId | sourceDocumentId; source tuple identity |
| producer | sourceModule MOD-0178, sourceType WAREHOUSE_OUTBOUND |
| warehouseId | warehouseReferenceId |
| ordered lines | deterministic strings 1..N; array order retained in snapshot |
| itemId / skuId / quantity / uomId | preserve identities and decimal strings; no float conversion |
| readyAt | plannedShipAt, normalized UTC instant |
| absent readyAt | first successful fetch UTC, persisted once |
| absent delivery/reference | plannedDeliverAt null; inventoryReferenceId null |
| structured shipTo | warehouse-outbound:{escaped outboundId}:ship-to |
| orderRef / full address / line metadata / lot / serial / packages | confidential canonical snapshot only |
| new local lifecycle | Draft |

The mapper validates the resulting command against the existing Shipment
validator before preparation, rejecting an otherwise legal Warehouse value that
cannot form a valid Shipment. No extra frozen DTO properties are introduced.

InventoryReadClient supports only GET availability and balance, with the frozen
item/SKU/level/warehouse/location/lot filters and tenant/LE headers. It cannot
write movements and has no Mongo dependency. Supplied echoed identity/scope must
match the request. Missing Inventory references are recorded NotApplicable in
source defaults; outbound/order/lot IDs are never invented as Inventory references.
The current Warehouse contract has no applicable Inventory-reference field, so
automatic inventory reconciliation is not inferred. The callable read seam is
tested separately with explicit valid references. Errors return explicit
DEPENDENCY_HTTP_404/503, DEPENDENCY_TIMEOUT, DEPENDENCY_UNAVAILABLE or
SCHEMA_INCOMPATIBLE and never mutate Shipment/stock state.

## Source-link persistence and recovery

Three confidential, scoped internal collections:
- sce_shipment_source_intents: durable preparation, selected UUIDs/defaults,
  complete immutable canonical snapshot/hash, mapping version and Pending/Committed.
- sce_shipment_source_links: atomic committed source tuple, Shipment ID,
  root correlation, defaults, snapshot/hash, mapping version and command ID.
- sce_shipment_source_evidence: append-only scoped drift, quarantine and failure
  evidence, actor and observation time.

Key = SHA-256 of an unambiguous length-prefixed tuple
(TenantId,LegalEntityId,MOD-0178,WAREHOUSE_OUTBOUND,outboundId).
The tuple is also readable in source-link fields. Unique scoped indexes and
deterministic document identity prevent duplicate links. Canonicalization sorts
object keys and preserves array order and exact scalar values.

Preparation is explicitly not the committed source claim. It survives a failed
creation so Shipment/command/history/audit/event/receipt UUIDs, root and planning
defaults are reused. The source link, Shipment, initial lifecycle, audit, receipt,
outbox and intent-state transition commit in the same Mongo transaction.
A precommit failure rolls all six committed collections back; only the pending
preparation and explicit failure evidence remain. Concurrent attempts share the
prepared identity and use Mongo transaction/unique-key arbitration; no separate
lease is needed because no partially committed source claim can be visible.

Identical replay returns the existing identity without history/receipt/audit/
outbox/link writes. Cancellation retains the reserved link. Soft deletion also
retains the link but returns blocked/not-found with no deleted aggregate data.
It never reopens creation. Changed snapshots, including line order, quantity,
orderRef, warehouse/address, status or empty lines, produce durable drift
without overwrite. Pending retries and late conflicting root UUIDs fail closed.

## Scope / correlation / security

TrustedSourceContext has a private constructor and requires an already
authenticated principal with exactly matching tenant_id, legal_entity_id and sub,
nonempty scope UUIDs, and shipment-create permission. The internal caller must
supply the principal from successful authentication; this is not a new token
validation or actor-discovery mechanism. Missing/unauthenticated/mismatched scope
is rejected before dependency access.

Valid supplied UUID correlations are retained. Absent manual/poll-style roots
are generated once into the durable preparation. Non-UUID, empty or conflicting
payload/envelope/context roots are quarantined with original evidence.
A later root conflicting with the persisted root is quarantined rather than
replacing it. No LE inference from warehouse/order/payload/default is implemented.
