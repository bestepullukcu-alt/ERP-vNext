## 6. CT-Q9 — measured and chosen

`IInventoryLedgerRepository.PostAsync` opens its **own** Mongo session and transaction for each posting
(`InventoryLedgerRepository.cs` `PostAsync` → `StartSessionAsync` → `WithTransactionAsync`), takes ONE `LedgerPosting`, and
MongoDB has no nested transactions. The pack §5 seam is "the same `IInventoryLedgerRepository.PostAsync`", so a multi-line
decision **cannot** be written in one ledger transaction without changing ledger posting code outside pack §5.
→ **idempotent continue + retry** (CT-Q9 second branch): lines post in order under `quarantine:{decisionId}:{lineNo}`; a
committed key is answered from the ledger BEFORE posting (so a retry never trips the request fingerprint); a refused line
stops the run with `ApplyFailed` (posted lines stay, the record stays locked — contract §5: ApplyFailed is not terminal);
`reapplyDecision` re-runs with the same keys. The 0175 side of a successful run (Applied event, record updates, new records,
history) is ONE 0175 transaction guarded by the once-only `Applied` event. Proof: `A_line_already_committed_under_its_key_is_never_posted_twice`
(line 1 pre-committed under its key → engine posts only line 2) + sabotage (e).
