## 7. Assumptions and open items

- **ASSUMPTION-0175-Q4-01 (CT decision):** quarantineStock / blockStock keep refusing `signatureId` → FU-0175-Q4-SIGN.
- **ASSUMPTION-0175-Q4-01b:** pack §8 KQ-H "0175 apply movements (`sourceModule = MOD-0175` with a decision id)" is implemented by
  the movement's direction, not by `sourceModule`: postMovement accepts any source module, so trusting it would let any caller pass a
  retest-due lot. Every 0175 decision movement except a release keeps the stock out of use and passes; a release passes once the
  approved new retest date is on the lot (the pack's "after the new retest date is set"). Inbound into AVAILABLE is refused, into
  QUARANTINE passes.
- **ASSUMPTION-0175-Q4-02:** serial choice for the manual actions (system-chosen, intake order, open 0175 records excluded). A serial
  in a non-AVAILABLE bucket that no 0175 record names (e.g. QUALITY_INSPECTION posted by another module without a hold) could be
  picked — the ledger then refuses the movement (no silent mis-post).
- **ASSUMPTION-0175-Q4-03:** a Retest-mode key answers the holds it created; a stopped run is not continued under the same key
  (the buckets are the system's and change once posted) — a new key takes the remaining AVAILABLE buckets.
- **ASSUMPTION-0175-Q4-04:** the approval's lot history row carries "MOD-0175 approval {QKR}: {reason}" in `reason` with `source =
  api` — TRACE `LotChangeEntry.source` is a closed enum (`trace.openapi.yaml:363`) and contracts stay unchanged.
- **ASSUMPTION-0175-Q4-05:** pack §8 KQ-I step 2 says the Draft is created "inside the lot transaction". Measured: `ILotTransaction`
  exposes no session to another store (`LotRepository` is not in the seam list). The lot transaction writes nothing on
  PendingApproval, so nothing is split: the Draft is inserted right after in its own 0175 transaction (idempotent on the request
  key); submit and apply re-check the lot.
- No `LotChangeEntry` for setting / clearing the retest hold (it is not a lot attribute; `LotChangeAction` is a closed TRACE enum).
- **O-Q4-1** retest date extension via TRACE PATCH needs no quality decision (§4). **O-Q4-2** `getLotQualityStatus` (contract
  `/lots/{lotId}/quality-status`, Lots page "Onay bekliyor" badge) not built — Q5 with the Lots page 202 handling. **O-Q4-3** two
  LotRelease decisions of one lot submitted at the same instant both pass the waiting check (no record lock); the second approval
  then finds the lot Released (no change, no history row).
- `GetAvailabilityHandler` (pack seam) needed no change: its held-lot filter reads `HeldLotIdsAsync`.
