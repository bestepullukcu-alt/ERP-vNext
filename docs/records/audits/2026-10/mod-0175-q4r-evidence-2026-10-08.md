## 5. Index build — measured

Own mongod (EphemeralMongo, random port 56189; never 27017), `QuarantineIndexConfiguration.ApplyAsync` (the step `InventoryIndexInitializerHostedService` runs before the host serves):

1. database holding **two open LotRelease decisions of one lot** (pre-Q4R data): **OK** — `ux_quarantine_lot_release_open unique=true key={TenantId, LegalEntityId, LotId}`. The index lives on a NEW collection, so old decisions can never block it; the next request for that lot adopts the oldest open one.
2. claim collection holding a duplicate (impossible through the code): `MongoCommandException DuplicateKey` → the startup gate logs critical and **refuses to start** (existing fail-closed behaviour).

On the owner's database the index is created the next time InventoryService starts (empty collection — cannot fail on existing data). Not started here (the owner's fleet was not touched).
