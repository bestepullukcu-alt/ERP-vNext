## 8. Slice assumptions (ASSUMPTION-0174-P2-…)

| # | assumption |
|---|---|
| P2-01 | A ledger `lotId` is a registered lot only in the canonical lower-case UUID form. Any other text is a typed lot (W-UI-02 typed lots are upper-case `[A-Z0-9./-]`). A canonical id that is not a lot of the tenant is `UNKNOWN_LOT`. |
| P2-02 | The serial lifecycle runs for serial-controlled products. A REVERSAL re-runs it only on the serials the registry knows and never creates a serial. |
| P2-03 | Switch off and lot not registered: an outbound / transfer serial unknown to the registry passes, with no registry write (pre-P2 stock). With a registered lot, or with the switch on, it is `SERIAL_NOT_AVAILABLE`. |
| P2-04 | Registry numbers are normalised by `LotIdentityPolicy` (trim + upper). The ledger keeps the posted strings (ASSUMPTION-0174-04). Two entries that normalise to one serial are `SERIAL_ALREADY_EXISTS` (inbound) or `SERIAL_NOT_AVAILABLE` (outbound). |
| P2-05 | `SERIAL_LOT_MISMATCH` = the serial's lot ≠ the movement's registered lot (null = typed / none). |
| P2-06 | CT-D1 uses the STORED lot status (Blocked / Expired). Expiry by date refuses postings immediately but leaves availability until the sweeper runs, at most 15 minutes later. |
| P2-07 | Blocking is never refused because of reservations. A SKU can become over-reserved, and the unchanged S2 guards then refuse new reservations and non-matching issues. |
| P2-08 | `inventory_lot_positions` holds registered lots only, with no backfill; typed lots get positions when P4 re-keys them. |
| P2-09 | `stockSummary` is absent while the lot has no position in the caller's company. On the list it appears only with `includeStock=true`. |
| P2-10 | A Consumed serial received again (a return, or a reversal of an issue) becomes Active in the receiving company and location. |
| P2-11 | The ledger does not check the serial shape: §12 lists 3–24 under UI-only rules, and the S1 test posts `S1`. |
